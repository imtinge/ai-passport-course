# 0. 不懂硬件也能看懂：先认识这十几个词

这一章是给**写过代码但没摸过电路**的人准备的。

如果你看到"ADC 分压""I2S 全双工""没有 PSRAM"这类句子会本能地跳过，
那这一章就是给你写的。好消息是：**这些概念在你熟悉的东西里都有对应物**，
你不需要学电子学，只需要把名词翻译一遍。

读完这一章，第 1 章开始的硬件描述你就能看懂了。

> 本书的数字都标了出处。这一章的规格来自
> `docs/hardware-design/specifications.zh_CN.md`、
> `components/bsp/include/bsp_pins.h` 和 ESP-IDF 的 `soc_caps.h`。

---

## 0.1 先做一张对照表

把这块板子想成一台**极度缩水的电脑**，你会立刻熟悉起来：

| 你的电脑 | 这块板子 | 差多少 |
| --- | --- | --- |
| CPU（i7 / M3） | **ESP32-C3**，RISC-V 32 位单核，**160 MHz** | 主频差 20 倍，且**只有一个核** |
| 内存条（16 GB） | **SRAM 约 400 KB**（芯片内部） | 差 **4 万倍** |
| 外挂内存条 | **没有**（没有 PSRAM） | 见 0.3，这是全书最大约束 |
| 固态硬盘（512 GB） | **Flash 8 MB** | 差 6 万倍 |
| 显卡 | **没有**。屏幕靠 CPU 一个像素一个像素推 | 没有硬件加速 |
| 操作系统 | **FreeRTOS**（任务 + 抢占式调度） | 几十 KB 级的"操作系统" |
| USB 口 / 主板插槽 | **GPIO 引脚**，共 **22 个**（GPIO0~GPIO21） | 数量极其有限 |
| 键盘鼠标 | **三个按键**，而且**合用一个 ADC 引脚** | 见 0.5 |
| 声卡 | **ES8311 codec** 芯片 | 需要你按时钟节拍喂数据 |

一句话总结：**这是一台内存 400 KB、硬盘 8 MB、单核 160 MHz 的电脑。**
你写 C 的经验大部分还有效，但"随手 malloc 一个 1 MB 数组"这种习惯必须改掉。

## 0.2 MCU：把整台电脑装进一颗芯片

**MCU** = Microcontroller Unit，微控制器，也叫"单片机"。

它和普通 CPU 的区别不在于"慢"，而在于**集成度**：

- 你的电脑：CPU、内存、硬盘、网卡是**分开的几块硬件**，插在主板上互相连接；
- MCU：**CPU + 内存 + Flash + 各种外设控制器，全都在一颗芯片里**。

所以你会看到"SoC"（System on Chip）和"MCU"在这里基本是同义词——
`components/bsp/include/bsp_pins.h` 里管它叫"芯片"，规格表里写 **ESP32-C3**。

对程序员来说，这带来一个直接后果：

> **外设不是"外部设备"，而是芯片里的一组寄存器。**
> 你调 `bsp_i2c_init()`，本质是配置芯片内部的 I2C 控制器寄存器。
> 没有"设备管理器"，没有热插拔，**接错了就是接错了**。

## 0.3 三种存储器：SRAM、Flash、PSRAM

这是全书最重要的一组概念，因为**"没有 PSRAM"决定了这本书里所有奇怪的写法**。

### SRAM（内存）—— 快、小、断电全丢

**SRAM** = Static RAM，静态随机存取存储器。就是"内存"。

- **位置**：芯片内部。ESP32-C3 约 **400 KB**。
- **速度**：和 CPU 同数量级，可以按字节随便读写。
- **断电**：**全部丢失**。
- **装什么**：全局变量、栈、堆（`malloc` 出来的东西）、LVGL 的绘制缓冲。

因为 Bootloader、FreeRTOS、Wi-Fi 协议栈都要占一部分，
**你实际能用的堆大约 230 KB**。
更狠的是：这 230 KB 还是碎片化的，**最大的连续空闲块不到 8 KB**
——所以 `malloc(100 * 1024)` 可能失败，即使"总空闲"看起来够。

### Flash（硬盘）—— 慢、大、断电保留

**Flash** = 闪存。就是"硬盘"，本设备 **8 MB**。

- **装什么**：你的程序代码、分区表、`const` 数据、图片、音频、NVS 设置。
- **断电**：保留。
- **读写规则不一样**：
  - **读**很快（通过 cache 和 MMU 映射到地址空间，代码就是直接在 Flash 上执行的）；
  - **写**很麻烦——**必须先整块擦除，再写入**，而且**擦写次数有限**（约 10 万次）。

这就是为什么 NVS（Flash 上的键值存储）不能拿来记"每秒变化一次的东西"
——第 9 章会讲怎么算磨损。

> ⚠ **`const` 在嵌入式里不只是"不可写"**
>
> 这是纯软件背景的人最容易踩的认知差。在 PC 上，`const` 只是一个编译期约定；
> 在这里，**`const` 决定数据放在 Flash 还是 RAM**：
>
> ```c
> const uint8_t img[] = {...};   // → Flash（.rodata），不占 RAM
>       uint8_t buf[] = {...};   // → RAM，启动时还要从 Flash 拷一份进来
> ```
>
> 同样的 100 KB 图片，前者占 0 字节 RAM，后者占 100 KB RAM（而且启动要拷贝）。
> 这就是为什么全书反复强调"**能 `const` 就 `const`**"。

### PSRAM（外挂内存）—— 这台机器没有

**PSRAM** = Pseudo Static RAM。可以理解为"焊在板子上的一条额外内存条"，
通过 SPI 接口挂在外面，能给你额外几 MB 的 RAM。

**ESP32-C3 上没有。** 官方规格表白纸黑字写着"8 MB Flash，**无 PSRAM**"。

这件事有多重要？社区里几乎所有"为什么这段代码要写得这么绕"的答案都是它：

- 图片**不能**在设备上解码（解码要一整帧缓冲）→ 必须在 PC 上预转（第 20 章）；
- 录音 3 秒就要 96 KB，而 96 KB **可能分配不到** → 必须检查 `malloc` 返回值（第 21 章）；
- LVGL 绘制缓冲只能用 **40 行**（约 19.2 KB）而不是整屏 → 只能局部刷新（第 5、11 章）；
- 不能用 LVGL 的 `clip_corner` 做全屏圆角 → 因为要生成 ARGB 图层，会撑爆 24 KB 的 LVGL 内存池。

**记住一句**：看到"无 PSRAM"，就自动翻译成"**任何超过几十 KB 的一次性分配都要打问号**"。

## 0.4 GPIO：一个你能读写的"位"

**GPIO** = General Purpose Input/Output，通用输入输出引脚。

**它是板子边缘那一个个金属焊盘/针脚，芯片一共 22 个（GPIO0~GPIO21）。**

把它想成一个特殊的变量：

```c
// 概念示意（真实 API 是 gpio_set_level()）
gpio[21] = 1;      // 输出高电平 → 引脚上出现 3.3V
gpio[21] = 0;      // 输出低电平 → 0V
int x = gpio[0];   // 输入：读引脚上现在是高还是低
```

区别在于：**这个"变量"真的连着物理世界**。写 1 就是让引脚输出 3.3 伏，
可能点亮一颗 LED；读到的 1，可能是某个按键被按下了。

### 三个必须知道的点

**一、一个引脚可以被"复用"。** 同一个物理引脚可以当 GPIO、也可以当 I2C 的 SDA、
也可以当 SPI 的 MOSI——由软件配置。**但同一时刻只能是一种**。
所以 `bsp_pins.h` 才被称为"引脚的单一事实来源"：它是这块板子的接线说明书。

**二、输出能力很有限。** GPIO 只能输出几十毫安，点亮一颗 LED 可以，
**直接驱动电机、继电器、大功率灯带会烧芯片**。要驱动大电流必须加驱动电路。
（本板的 `BSP_I2S_PA_CTRL` 是 `-1`，意思是功放使能脚根本没接到 MCU，功放是常通的。）

**三、不是每个引脚都能随便用。** 有些引脚有专门用途：
GPIO18/19 是 USB-Serial-JTAG（用来看日志和烧录），
GPIO9 是**启动模式选择脚**（救砖时要拉低它，见第 3 章）。
改引脚之前先查 `bsp_pins.h`。

## 0.5 ADC：把"电压"变成"数字"

**ADC** = Analog-to-Digital Converter，模数转换器。

现实世界是连续的（电压可以是 3.300001V），计算机只认离散的数字。
ADC 就是中间的翻译器：**读一个电压，输出一个整数**。

- ESP32-C3 的 ADC 是 **12 位** → 输出范围 **0 ~ 4095**；
- 读数单位是**毫伏**时，量程由"衰减（atten）"设置决定。

### 本板的绝妙用法：三个按键只用一个引脚

这是理解 ADC 最好的例子，也解释了第 1 章那张奇怪的电路图。

```text
3.3V ── 上拉 10k ──┬── GPIO0（ADC1_CH0）
                   └── 按键 ── 分压电阻 ── GND
```

三个键分别串不同阻值的电阻，按下时把 GPIO0 拉到不同的电压：

| 按键 | 串联电阻 | 电压 | 判定窗口 |
| --- | --- | --- | --- |
| 上 | 0 Ω | **0 mV** | `{0, 150}` |
| 下 | 1 kΩ | ≈ **300 mV** | `{150, 447}` |
| 确定 | 2.2 kΩ | ≈ **595 mV** | `{447, 1900}` |
| 松开 | 断开 | **3300 mV**（被上拉电阻拉高） | — |

代码只需要读一次电压，落在哪个窗口就是哪个键。
**三个键，只占一个引脚**——在这台只有 22 个引脚的设备上，这很关键。

三个由此而来的细节：

1. **上拉电阻**：松开时没有通路，引脚是"悬空"的（电平飘忽不定）。
   上拉电阻把它稳定地拉到 3.3V。
2. **为什么不能用芯片内部上拉**：`bsp_pins.h:48` 写明内部上拉约 **45 kΩ 且精度差**，
   会把三档电压全挤到 0~154 mV 并随温度漂移而重叠。**必须用外部 10 kΩ**。
3. **换了电阻怎么办**：`bsp_button_read_mv()` 能读实时电压。
   逐个按住三个键记下读数，取相邻两档中点，改 `BSP_BTN_MV_TABLE` 即可（第 6 章）。

## 0.6 四种"总线"：芯片和外设怎么说话

芯片要和外设（屏幕、音频芯片、电量计）通信，需要一套约定好的"说话方式"，
这就是**总线**。本板用到四种，记住它们的分工：

| 总线 | 几根线 | 速度 | 本板用在哪 | 一句话类比 |
| --- | --- | --- | --- | --- |
| **I2C** | 2（SDA 数据 + SCL 时钟） | 慢（本板 **100 kHz**） | ES8311 音频芯片（地址 `0x18`）、CW2017 电量计（`0x63`） | 一条走廊上有很多房间，**喊地址**才能和某个房间说话 |
| **SPI** | 4（CS 片选 + SCLK 时钟 + MOSI 发 + MISO 收） | 快（本板屏幕 **80 MHz**） | 屏幕 ST7789（MOSI=9, SCLK=8, CS=1, DC=20） | 点对点专线，**拉一根专用的片选线**来选中对方 |
| **I2S** | 5（MCLK 主时钟 + BCLK 位时钟 + WS 声道选择 + DIN/DOUT 数据） | 按音频节拍 | 音频（MCLK=6, BCLK=5, WS=3, DOUT=2, DIN=4） | 一条**永不停歇的传送带**，按固定节拍一格一格传音频样本 |
| **UART** | 2（TX 发 + RX 收） | 中等 | 日志输出、烧录 | 最古老的串行口，两个方向各一根线 |

几个容易混的点：

- **I2C 是"一主多从 + 地址寻址"**：两个芯片可以**共用同一条 I2C 总线**
  （本板的 ES8311 和 CW2017 就是这么接的），靠地址区分。
  这也是为什么 `bsp_audio_init()` 内部会调 `bsp_i2c_init()`——它们共享总线。
- **SPI 靠片选（CS）区分设备**，所以挂几个设备就要几根 CS 线。
  本板屏幕**没有 MISO**（`bsp_pins.h` 里只定义了 MOSI），
  因为**屏幕只收不发**——不需要读屏幕的数据。
- **I2S 是给音频专用的**，不要拿它传别的东西。它最大的特点是
  **必须持续供数据**：一旦断流，喇叭就会出杂音。
  这就是第 21 章"分块送、每块检查"的原因。
- **全双工** = 能同时收和发。本板 I2S 是"同端口一 tx 一 rx，共用 MCLK/BCLK/WS"，
  所以录音和播放可以走同一组时钟线。

### 顺带：PWM 和 DMA

**PWM**（Pulse Width Modulation，脉宽调制）：
一个引脚只能输出 0 或 3.3V，怎么调出"一半亮度"？
答案是**极快地开关**——开的时间占 60%，人眼/电感看到的就是 60% 的强度。
本板背光就是这样调的：GPIO21 走 LEDC（ESP32 的 PWM 外设），**5 kHz、10 位分辨率**。

**DMA**（Direct Memory Access，直接内存访问）：
让硬件自己去内存里搬数据，**不经过 CPU**。
屏幕刷屏、I2S 送音频都靠它。
代价是**DMA 要求物理连续的内存**——这又回到了
"最大连续空闲块 < 8 KB"那个约束。

## 0.7 剩下的高频词

| 词 | 是什么 | 你需要知道什么 |
| --- | --- | --- |
| **中断 / ISR** | 硬件事件打断 CPU 去处理的机制 | 回调里**不能干重活**（不能 `printf`、不能加锁太久） |
| **寄存器** | 外设的配置开关，本质是一个特殊地址上的整数 | BSP 帮你封装了，一般不用直接碰 |
| **时钟 / 晶振** | 给芯片打拍子的振荡器；本板 CPU **160 MHz** | 外设速度都是它分频出来的 |
| **上拉 / 下拉电阻** | 把悬空引脚稳定拉到高/低电平的电阻 | 三键电路必须外部 10 kΩ，见 0.5 |
| **看门狗 WDT** | 检测程序卡死并自动复位的计时器 | 任务里长时间阻塞会触发它 → 设备重启 |
| **复位 / RESET** | 让芯片重新开始运行 | 屏幕 `BSP_LCD_RST` 是 `-1`（没接 MCU），走软件复位 |
| **codec** | 编解码芯片 = DAC（数字转模拟）+ ADC（模拟转数字） | 本板是 **ES8311**，喇叭和麦克风都接它 |
| **深睡 / 浅睡** | 两种省电状态 | 深睡几乎全断电（只有 RTC 域活着），唤醒=重启；浅睡保留 RAM |
| **RTC 域** | 深睡时还通电的一小块电路 | `RTC_DATA_ATTR` 变量放这里，深睡后还在 |
| **bare metal / RTOS** | 裸机 / 带实时操作系统 | 本书用 FreeRTOS，可以有多个"任务" |
| **NFC** | 近距离无线通信 | 本板是**被动** NTAG213 标签（只是可被读写的标签，不能主动读别人） |

## 0.9 纯软件背景的人，最容易误解的五件事

**一、`const` 是存储位置，不只是只读。** 见 0.3。这是本书出现频率最高的一条纪律。

**二、硬件会失败，而且失败是常态。**
每个 `bsp_xxx_init()` 都可能返回错误——I2C 上没这个芯片、电池没电、SPI 接触不良。
**不要写 `bsp_audio_init();` 然后不管返回值。**
官方 `main.c` 的做法是分层：UI 载体（屏幕）失败就退出，
可选外设（音频/电量/Wi-Fi）失败只打个 `[FAIL]` 标记继续跑。

**三、"延时"不是为了让编译器高兴。**
`vTaskDelay()`、长按判定的 500 ms、SPI 的 80 MHz，都是真实的物理时序。
改快了外设可能不认，改慢了用户会觉得卡。

**四、总线是共享的，速度受最慢的那个限制。**
I2C 上挂了两个芯片，它们共享 100 kHz 的带宽；
屏幕 SPI 和音频 I2S 竞争同一块 DMA 内存。
"为什么加了音频之后屏幕卡了"——这类问题都出在这里。

**五、引脚是有限资源，而且要"复用"。**
22 个引脚要塞下屏幕、音频、I2C、按键、USB、启动模式。
想在上面再加一个传感器？先查 `bsp_pins.h`，看还剩什么。
