# 23. 下一步：练习路线

读完这本书，你需要的是**动手**。本章给一条有梯度的练习路线，
每一步都有明确的“做完了”的判断标准。

## 23.1 五个练习，从易到难

### 练习 1：改出一个自己的页面（1–2 小时）

**目标**：在官方基线的菜单里加一个你自己的页面。

步骤：
1. 复制 `main/demo_battery.c`，改名 `demo_hello.c`；
2. 改 `enter()`：画一个自己的界面（标题 + 两行文字 + 一个色块）；
3. 在 `main.c` 的 `DEMOS[]` 表里加一行；
4. 在 `main/CMakeLists.txt` 的 `SRCS` 里加上新文件。

**做完了的标准**：烧进去能用上下键选中、确定键进入、长按返回。

**这一步会踩到的坑**（都是好事）：忘了加 `SRCS`、忘了 `REQUIRES`、
忘了在 `exit` 里删 timer。

### 练习 2：做一个计数器（半天）

**目标**：做一个按键计数器，数值存进 NVS。

要点：
- 上下键加减，确定键保存；
- 用 `nvs_set_i32` / `nvs_get_i32`；
- **记得 `nvs_commit()`**；
- 重启后数字还在。

**做完了的标准**：断电再上电，数字还在。

### 练习 3：做一个计时器（1 天）

**目标**：秒表——确定键开始/暂停，上下键清零。

要点：
- 用 `lv_timer` 每 100 ms 刷新一次显示；
- 时间用 `esp_timer_get_time()`（不要靠 `lv_timer` 计数，它会漂移）；
- 页面退出时 `lv_timer_delete`。

**做完了的标准**：跑 60 秒，误差小于 0.5 秒。

### 练习 4：做一个音效板（2–3 天）

**目标**：三个按键各播一个音效。

要点：
- 素材用 `EMBED_FILES` 编进固件（小音效）或 SPIFFS 分区（多个音效）；
- **播放必须在独立任务里**；
- 用**常驻任务 + 静态栈**（照抄第 15 章）；
- 每帧检查 `stop` 标志，能打断。

**做完了的标准**：连按 20 次不出问题（这是在验证你没有堆碎片化）。

### 练习 5：做一个联网看板（3–5 天）

**目标**：联网拉一个 API（天气/行情/一言），显示在屏幕上。

要点（对应 [10 连上](10-network.md) / [10b 配好](10b-provisioning.md) / [10c 取到](10c-network-data.md)）：

- Wi-Fi 连接要有**降级**：没网显示上次数据 + 离线标记（10c.7）；
- 重连要**退避 + 上限**，并把断开 `reason` 打出来（10.3，可抄 `snippets/08`）；
- **密码不要硬编码**——至少留一条配网/串口写入的路（10b）；
- HTTP 要设 `timeout_ms`、响应**分块读**、设硬上限（10c.1，可抄 `snippets/09`）；
- HTTPS 前**先 SNTP 校时**（10c.2）；
- 刷新**节流**（至少间隔 1 分钟），屏灭不刷（10.7）；
- 联网任务**不要挂在页面上**（照抄第 16 章的 world 任务思路）。

**做完了的标准**：断网后不崩、不卡，恢复网络后自动恢复；
反复进出页面后内存回到同一条基线。

## 23.2 一条重要的社区规则

在你准备发布自己的应用之前，请知道这条官方规则：

> **《衍生应用必须重新设计 UI》**
> "Reusing the current demo test menu, screens, or visual shell is prohibited;
> renaming, recoloring, or adding a feature to that shell does not count as a
> redesign. BSP APIs and non-UI logic remain reusable."

翻译成人话：

- ❌ 把官方 demo 菜单换个颜色、加个入口 → 不算；
- ❌ 沿用官方的方格卡片菜单布局（截至 2026-10-07 是 **7** 个卡片，会随官方更新变化）→ 不算；
- ✅ **自己设计一套界面** → 算；
- ✅ BSP 和所有非 UI 逻辑随便复用 → 完全允许。

**这不是形式主义**：官方 demo 的界面是“硬件测试面板”，
它的信息架构是为“验证外设”设计的，不是为“给用户玩”设计的。

## 23.3 发布前自查清单

- [ ] 界面是自己设计的（不是 demo 换皮）？
- [ ] 所有按键语义符合全局约定（上下导航、确定进入、长按返回）？
- [ ] 所有非 LVGL 任务都加了 `bsp_lvgl_lock()`？
- [ ] 页面退出时先删 timer 再删 screen？
- [ ] 所有可能失败的外设调用都有降级（电量 `-1`、网络超时）？
- [ ] `esp_get_minimum_free_heap_size()` 是否 > 30 KB？
- [ ] 关掉了不用的协议栈（IPv6、BT）？
- [ ] 没有在栈上开超过 1 KB 的数组？
- [ ] README 写明了 IDF 版本和构建命令？
- [ ] 跑过 `tools/validate.sh`？
- [ ] **真机上验证过**（不是只编译通过）？

## 23.4 关于 IDF 版本迁移

如果你现在才开始新项目，建议的判断：

| 你的目标 | 版本选择 |
| --- | --- |
| 学习 / 做普通玩法 | 5.5.3（社区 105/110 个仓库在这条线上，参考资料最多） |
| 做 AI 语音对话 | **6.1**（官方已放弃 5.x） |
| 长期维护的新项目 | 6.1（迁移窗口正在打开，现在上车最省事） |

现状数据（作者本地扫描 172 个仓库，数据截至 2026-10-07）：明示版本的 110 个里 **105 个还在 5.5**，
只有 4 个上了 6.x。**但官方主仓已经声明 5.x 不再支持**——
这个分布会在接下来半年快速变化。

## 23.5 社区资源怎么用

社区里有 **300+** 个真实仓库可以借鉴（作者本地扫描过 172 个样本，完整统计见附录 B.6）。用法：

1. **想做某个玩法 → 先找最接近的 2–3 个仓库**（附录 B 有索引）；
2. **读它们的 README 和 `app_main`**，不要一上来就读全部代码；
3. **只提取需要的模式，不要把整个分支合并进来**——
   官方明确要求避免带入旧 BSP 和旧配置；
4. **优先复用 `components/bsp/` 里的 `bsp_*` API**，不要重写驱动。

### 官方仓库的 `demo/*` 示例分支：不用切换工作区就能读

官方仓库除了 `main`，还挂了一批 `demo/*` 分支，每个都是从基线演化出的**完整应用**。
这是比社区 fork 更干净的范本——它们跟着基线走，不会带一堆旧配置。

在我核对时的仓库状态（`git branch -r --list 'origin/demo/*'`）实际有 **11 条**（数据截至 2026-10-07，会变化）：

| 分支 | 类型 | 值得学什么 |
| --- | --- | --- |
| `demo/stopwatch` | 秒表 | 最小应用；纯逻辑与 UI 分离；主机测试 |
| `demo/cat-themed-pomodoro-timer` | 番茄钟 | 单调时钟、暂停恢复、**NVS 断电保存** |
| `demo/rock-paper-scissors` | 石头剪刀布 | RGB565 图片素材管线、Flash 预算 |
| `demo/tetris-game` | 俄罗斯方块 | 游戏循环、`PRESS` 低延迟按键、局部刷新、音效 |
| `demo/claude-buddy-port` | 桌面伴侣 | 完整架构、加密 BLE、协议解析 |
| `demo/blufi-provisioning` | 配网 | BluFi 配网流程 |
| `demo/recovery-ble` | 恢复模式 | BLE 救砖/恢复通道 |
| `demo/funbox-11-in-1` | 合集 | 一个固件装多个玩法 |
| `demo/white-rabbit-pet`、`demo/tamagezi`、`demo/coloros-muyu` | 电子宠物/小游戏 | 养成与动画循环 |

**不切换分支也能看**（这条命令值得记住）：

```bash
git branch -r --list 'origin/demo/*'                  # 列出所有示例分支
git show origin/demo/stopwatch:main/main.c            # 直接看某个分支的某个文件
git diff main...origin/demo/tetris-game -- main components   # 看它改了什么
```

> 分支列表会随仓库演进而变化——**用上面第一条命令自己查一遍**，
> 别把这张表当成定论。

### Git 工作流（官方约定）

```bash
git switch main && git pull
git switch -c feature/my-app      # 你的作品在 feature/* 分支开发
```

**不要**直接在 `main` 上做应用，也**不要**把多个 demo 分支整体合并——
它们改了同一套菜单和配置，互相会冲突。
正确姿势是**提取模式**（状态机怎么写、素材怎么转、任务怎么停），
而不是复制整个分支。

## 23.6 你现在应该已经建立起来的直觉

如果这本书起作用了，你应该会在写代码时**自动**想到这些：

- “这个数组超过 1 KB，放栈上会炸” → `static`；
- “这个回调里不能播音频” → 入队；
- “我要在非 LVGL 任务里改 UI” → 加锁；
- “我要删页面了” → 先停 timer；
- “NVS 写完了” → commit 了吗？
- “这个素材 200 KB” → 不能 EMBED，要开分区；
- “flash 上越界读” → 不会崩，只会静默错；
- “总空闲堆够” → 但连续块够吗？

这些直觉比任何 API 都值钱。

## 23.7 最后一句

AI Passport 的社区有个特点：**绝大多数项目都在 200 个文件以内**，
中位数是 181 个文件。

这意味着——**你能做完的东西，比你以为的要多。**
重的是素材和耐心，不是代码量。

如果你读完这本书，想把“写下一个玩法”交给 AI 来做：官方仓库另有一套**给 AI 看的开发约定**——
`AGENTS.md` / `skills/` / 契约体系（接口契约、提交规范、UI 必须重设计的红线等）。
那是本书的“AI 版对应物”，本书不展开讲（前言也说过，这本书写给人读，不教提示词）。

你 clone 官方仓后就能看到这套文件。用它有个前提：**你已经能用本书的知识看懂它生成的代码**——
否则 AI 写出来的硬件坑你没法验，反而更危险。
