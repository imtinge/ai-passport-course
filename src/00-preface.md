# 前言：这本书给谁

## 你要是这两类人，请合上这本书

**第一类：想要一份"AI 提示词模板"的人。** 这本书里没有提示词，没有 AGENTS.md 模板，
也没有"复制这段话给 AI 就能生成应用"的咒语。社区里确实有大量给 AI 看的文档
（作者本地扫描 172 个社区仓库，约 70% 带 `AGENTS.md`），但那些东西对你理解硬件没有帮助。
这本书是写给人读的。

**第二类：想找一份 ESP-IDF 官方手册的人。** ESP-IDF 的官方文档有上万页，
本书一页都不会重复。本书只讲**在 AI Passport 这块具体板子上**，
哪些 API 你真的会用到、怎么组合、坑在哪。

## 这本书的读者长这样

- 写过 C：知道指针、结构体、`malloc`、头文件、Makefile 大概是怎么回事；
- **没碰过 ESP-IDF**，甚至没做过嵌入式；
- 手上有一块 FoloToy AI Passport（或者正准备买），想给它写点自己的东西；
- 遇到"为什么这样写"会不舒服，想知道原因。

如果你符合，这本书就是给你写的。第 2 章专门用你已有的 C 知识去类比 ESP-IDF 的概念，
不需要先去啃官方手册。

**如果你连 MCU / SRAM / GPIO / 总线 这些词也陌生**，别急着从第 1 章开始——
先看 **第 0 章《不懂硬件也能看懂：先认识这十几个词》**。那一章用"把这台板子当成一台
极度缩水的电脑"的类比，把 MCU、SRAM、Flash、PSRAM、GPIO、ADC、I2C、I2S 等专有词
逐个翻译成你熟悉的东西，所有数字都标了源码出处。读完它，第 1 章的硬件描述你就能无障碍跟进了。

## 读完你能做到什么

不是"跑通 demo"，而是这四件事：

1. **看懂任何一个社区仓库的代码结构**——知道 `main/` 里那一堆文件各自负责什么，
   从哪里开始读；
2. **从零写一个自己的玩法**——按键怎么接、界面怎么画、声音怎么放、数据怎么存、
   电量怎么显示，全都有可复制的骨架；
3. **知道什么不该做**——在没有 PSRAM 的 400 KB 内存里，很多 PC 上的常识是错的，
   本书会把这些"反常识"单独拎出来；
4. **踩坑时能自己定位**——看门狗重启、栈溢出、黑屏、`adc1 is already in use`，
   每一种都有确定的排查路径。

## 一个贯穿全书的前提

AI Passport 是 **ESP32-C3 + 8 MB Flash + 无 PSRAM**。
"无 PSRAM"这五个字，是本书一半内容的成因。

在 PC 上，你申请 150 KB 的帧缓冲不会有人眨一下眼。在这块板子上，
开机后最大的连续空闲内存块不到 8 KB——连一整屏 240×320 的画面都放不下。
于是社区里所有的"奇怪写法"：分条刷屏、静态栈、内存映射、单块解压，
都是为了绕过这一个问题。

理解了这一点，你再看那些代码，就不是"炫技"，而是"别无选择"。

## 事实来源的优先级

硬件细节在不同文档里可能冲突。官方规定的优先级顺序是：

```c
产品规格与实测结果
  → components/bsp/include/bsp_pins.h
    → BSP 头文件与实现
      → 硬件指南
        → README / demo 代码
```

本书遵循同一顺序。**当 `bsp_pins.h` 和某篇 README 打架时，信 `bsp_pins.h`。**

### 本书的做法：能查源码的，就不写"据说"

书里的关键数字——引脚、电压窗口、分区表、刷新周期、任务优先级与栈大小、
LVGL 与组件版本——都是**打开仓库文件逐条核对过的**，并在正文里标了出处
（`main/main.c:175`、`bsp_display_lvgl.c:84`、esp_lvgl_port 的
`ESP_LVGL_PORT_INIT_CONFIG()` 之类）。

这样做的原因很实在：社区里流传着不少**互相矛盾的数字**，而它们往往都"有出处"——
只不过出自不同 fork 的旧配置。举两个真实例子：

- 你会看到注释写"优先级 4 —— 低于 **LVGL（5）**"。官方基线的 LVGL 任务其实是 **4**；
  那句注释出自某个 fork 自己的 sdkconfig。
- 你会看到"app 分区上限 **3 MB**"。官方默认 `factory` 约 **7.9 MB**；
  3 MB 是 PokeWalk 为了塞 recovery 自己定的契约。
- 你会看到"屏幕 SPI 是 **40 MHz**"。官方 `docs/README.zh_CN.md` 的硬件能力表确实这么写，
  第三方实测贴也跟着抄了这个数；但 `components/bsp/include/bsp_pins.h` 里的
  `BSP_LCD_PCLK_HZ` 是 **80 MHz**，同仓库的硬件开发指南也写 80 MHz。
  那张摘要表没跟上源码——**看 `bsp_pins.h`**。
- 你会看到电池标 **500 mAh**。官网商品页写 500 mAh，而 BSP 内置的 CW2017 profile 是
  **520 mAh**（厂家为优特利 520 mAh 电芯生成的 80 字节 profile）。SOC% 按 520 那条曲线算。
  两个数字都没错，只是**一个是标称容量、一个是电量计算法用的容量**。

所以这本书给数字时会同时给你**出处和判断方法**。
**思路可以照抄，数字请回到你手上的源码再确认一遍。**

顺带一提：官方仓库 `folotoy/ai-passport` **开机进七卡片测试菜单**（Display / Button / Audio /
Battery / Wi-Fi / BLE / Low Power 七项），没有"开机直达某个玩法"的机制，也没有 `BOOT_DEMO_INDEX`
这种宏。

第 18 章的「巴巴爸爸图鉴」**不是官方内容**——它是作者（你）用 **Trae** 在自己的工作副本里
生成的实战项目，被放在「实战拆解」部分当范例；官方仓库里既没有 `demo_barbapapa.c`，也没有开机
直达它的任何代码。你 clone 到官方仓库看到七卡片菜单是正常预期。
